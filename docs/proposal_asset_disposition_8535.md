## 三、为什么没有备份这 8535 个？

### 原因 1: 存储成本

```
8535 个提案 × ~1.5 KB/个 = ~12.8 MB
+ 关联 checkpoint: ~400 MB
+ 关联 prescreen: ~50 MB
总计: ~463 MB

vs 核心资产 202 个:
202 × 1.5 KB = ~0.3 MB
+ checkpoint: ~10 MB
总计: ~10.3 MB
```

**结论**: 备份全部 8535 个的成本是核心资产的 45 倍，但价值远低于 45 倍。

---

### 原因 2: 信息密度低

```
8535 个非核心提案的信息密度:
├─ 6593 个 archive: 旧 schema + 废弃协变量 → 信息密度 ≈ 0
├─ 2800 个 prescreen 失败: 未评估 → 信息密度 = 未知
├─ 1877 个未评估: 未评估 → 信息密度 = 未知
└─ 1500 个未通过 gate: 信息密度低 (dir_acc < 0.52)

vs 核心资产 202 个:
└─ 信息密度高 (dir_acc ≥ 0.52, S/A tier)
```

---

### 原因 3: 可复现性

```
8535 个非核心提案的可复现性:
├─ Archive 6593: 可复现 (旧版 peer + 旧版数据)
├─ Prescreen 失败 2800: 可复现 (重新生成 + 等 Laya 恢复)
├─ 未评估 1877: 可复现 (重新进入评估队列)
└─ 未通过 gate 1500: 可复现 (重新评估)

vs 核心资产 202:
└─ 不可复现 (特定数据窗口 + 特定随机种子 + 特定 peer 状态)
```

**结论**: 非核心提案可复现，核心资产不可复现 → 优先备份核心资产。

## 六、常见问题

### Q1: 为什么不直接删除这 8535 个？

**A**: 保留审计轨迹 + 可复现性研究。压缩归档而非删除。

### Q2: 未来会不会需要这些提案？

**A**: 可能。但概率低 (< 5%)，且可复现。建议保留压缩归档 6 个月，之后可删除。

### Q3: 如何区分"可复现"和"不可复现"？

**A**: 
- **不可复现**: 依赖特定数据窗口 + 特定随机种子 + 特定 peer 状态 → 核心资产
- **可复现**: 仅依赖 peer 提示 + 数据 → 非核心资产

### Q4: 备份策略的成本效益？

**A**: 
- 备份 202 核心: 10 MB, 价值 100%
- 备份 1120 次核心: 50 MB, 价值 30%
- 备份 8535 全部: 463 MB, 价值 < 5%

**结论**: 备份核心 + 次核心即可，不必备份全部。
