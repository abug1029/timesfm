# oi_gated_momentum 协变量 Spec（v23 口径）v2

> 日期: 2026-09-18。v1: 方案一定标 + 门控结构修正（`0b4f796`）。
> **v2: 吸收宿主评审（Conditional Pass）的 3 项核心修订 + 4 项工程细节，处置记录见 §8。**
> 状态: **spec 修订版，未实施**。

## 1. 背景与决策

backlog 提案 `oi_weighted_momentum`（豆粕 m，momentum 族）机制成立，但存在两类缺陷：
scaling_factor 无定标规则（参数挖掘自由度），且 tanh 作用于价格×持仓**乘积**与机制
假设背离——异号乘积输出为负，减仓行情不但不衰减至零，反而发出反向信号（"反向反手
开仓"缺陷）。

定稿决策（v1 + v2 评审）：
1. **定标采用方案一（滚动分位数）**，并按 v2 评审对持仓项改用**单边非对称分位数**（§2.3）；
2. **结构修正**：价格与持仓解耦，持仓项仅作非负门控，方向由价格单独决定（§2.2）；
3. **对齐口径**：价格与持仓**同窗对齐**于最近已收盘交易日，杜绝相位错位（§3.2）；
4. **数据口径**：ΔOI 用全市场总持仓（KQ.i@m 指数合约），杜绝主力换月污染（§3.1）；
5. **评估口径**：门控型协变量按 **Active Directional Accuracy** 考核，防 0 信号
   稀释硬门（§5，v2 新增）。

## 2. 信号定义

### 2.1 原公式缺陷（修正依据）

| 行情 | ΔP | ΔOI | 乘积符号 | 原公式输出 | 机制预期 |
|---|---|---|---|---|---|
| 增仓上涨 | + | + | + | tanh(+) 做多 | ✅ 符合 |
| 减仓上涨 | + | − | − | tanh(−) **做空** | ❌ 应衰减至 0 |
| 增仓下跌 | − | + | − | tanh(−) 做空 | ✅ 符合 |
| 减仓下跌 | − | − | + | tanh(+) **做多** | ❌ 应衰减至 0 |

原公式实为"价仓同向顺势、背离反手"的振荡逆转策略，与"以增仓为量价验证门控的动量"
机制相反。

### 2.2 修正后信号（唯一正式定义）

$$
\text{Signal}_t = \tanh\bigl(\Delta P_{5d,t} \times \text{scale}_{P,t}\bigr) \times \max\bigl(0,\ \tanh(\Delta OI^{tot}_{5d,t} \times \text{scale}_{OI,t})\bigr)
$$

- **方向由价格单独决定**：tanh(ΔP×scale_P) 是有符号主项；
- **持仓项是非负门控**：max(0,·) 半波整流截断门——增仓时激活（0→1 渐变），
  减仓时**精确归零**。四象限行为与机制表完全一致。

**门控选型决策（冻结）**：选半波整流截断门，**不选 sigmoid**。理由：sigmoid 门在
减仓时仍输出正权重，给"减仓行情"保留信号权重，违背机制表格中"减仓→衰减至零"的
明确语义。门控语义优先于平滑性。

**时间下标与对齐规则（v2 写死，替代 v1 的"模块内 shift(1)"）**：

- ΔP_5d,t 与 ΔOI^tot_5d,t 使用**完全相同的 5 日窗口 [t−5, t]**，
  其中 **t = 最近已收盘交易日**（OI 取官方结算值）；
- **执行映射**（消除上下游歧义）：
  - T 日收盘前调仓 → t = T−1（价格与持仓都用 T−1 及更早）；
  - T 日收盘后（结算完成，15:00 后）调仓 → t = T；
  - **两种执行模式下价格与持仓永不错位**——"同窗"优先于"价格领先持仓一天"。
    相位错位的经济代价（当日巨量减仓打压价格、门控滞后一天才反应）被显式接受，
    因为错位口径下门控与方向项测量的是不同日期的市场状态，机制语义反而失真。
- **边界防护归属**：`t` 的"已收盘"判定由调用方现有的 `get_safe_daily`
  （`data/data_store.py:158`，date==today 且 hour<15 剔除）统一实施，
  **模块不内部 shift**——与全仓协变量管线同一套前视防线，不另立门户。

### 2.3 定标（方案一 v2 修订：价格对称、持仓单边）

**价格项（对称口径，不变）**：

$$
\text{scale}_{P,t} = \frac{1}{\text{RollingQuantile}_{K}\bigl(|\Delta P_{5d}|,\ 0.75\bigr)\ \text{于窗口 } [t{-}K,\ t{-}1]}
$$

价格收益率近似对称厚尾，绝对值分位数合理。q=0.75、K=120（固定）。

**持仓项（单边非对称口径，v2 修订）**：

$$
\text{scale}_{OI,t} = \frac{1}{\text{RollingQuantile}_{K}\bigl(\Delta OI^{tot}_{5d},\ 0.85\bigr)\ \text{于窗口 } [t{-}K,\ t{-}1]}
$$

**修订理由（v2）**：持仓变化率分布显著非对称——温和增仓常年 3~10%，减仓踩踏可爆发
至 20~30%。对 |ΔOI| 全量取绝对值分位数会让历史减仓踩踏推高上分位、标尺失准，正常
增仓行情下门控钝化在 0.2~0.4 区间、失去 tanh(1)≈0.76 的弹性拐点作用。改用**带符号
ΔOI 的 85% 分位**：门控只对正 ΔOI（增仓）激活，标尺就只该由增仓尾部定义；带符号
取分位数天然免疫负向极端值（它们落在分布下尾，不影响 85% 上分位）。无待调常数，
与方案一同一优雅性。q_OI=0.85、K=120（固定）。

**实证量级（豆粕 m，2016→2026 全库）**：|ΔP_5d| p75 = 2.94%，|ΔOI^tot_5d| p75 =
12.15%（主力单合约口径，仅供量级参照）。静态隐含 scale_P ≈ 34、scale_OI ≈ 8.2
（滚动时变，此处仅验证量级不锁数值）。

**算子口径（v2 代码级锁定）**：

- ΔP_5d,t = P_t/P_{t−5} − 1 ≡ `price.pct_change(5)`
- ΔOI^tot_5d,t = OI_t/OI_{t−5} − 1 ≡ `total_oi.pct_change(5)`
- **禁止 `diff(5)` 绝对差分**：持仓总基数随年份增长，绝对差分非平稳，跨期不可比。

## 3. 数据工程守则（防虚假阿尔法）

### 3.1 总持仓口径（数据前提，当前不满足——必须先补数）

**实证**：`futures_m.db` 的 `kline_1d` 仅含 1 个合约代码 `M_CONT`（TqSdk 主力连续
直连入库）。**库中不存在分合约数据**，主力单合约 OI 的 ΔOI_5d max = 154%（换月
翻倍特征），污染是现实而非假设。

**解决路径**：新增摄入 **TqSdk 指数合约 `KQ.i@m`** 日线（其 open_interest 天然等于
全市场总持仓）。回填 2016-01-05 → 今，入新表 `index_continuous_1d`
（dt, close_price, volume, open_interest），每日增量同步。模块对数据源无感知。

### 3.2 时序对齐（v2 重写）

- 官方持仓 T 日数据在 T 日结算后才发布 → **输入序列只允许含已收盘（已结算）bar**，
  由调用方 `get_safe_daily` 收盘掩码统一保证（§2.2）；
- 回测场景全部 bar 已收盘，与生产口径天然一致；
- **本 spec 下不存在的选项**：价格用 t、持仓用 t−1 的错位口径（v1 的
  "模块内 shift(1)" 已废除——它制造 §2.2 所述的相位错位）。

### 3.3 数值卫生（项目惯例 + v2 补全）

- 输入 NaN/inf/非数值（含 bool）→ 输出 NaN，**fail-closed**，不做静默填充；
- 定标分位数防御断言（v2，防除零/inf）：

```python
q_val = rolling_quantile(...)          # |ΔP| 的 75% 或 ΔOI 的 85%
scale = np.where(q_val > 1e-6, 1.0 / q_val, np.nan)   # 非正/缺失 → NaN, 绝不产生 inf
```

- 回测窗口起点前 K=120 日为定标预热期，输出 NaN；ΔP/ΔOI 5 日窗口不足 → NaN。

### 3.4 异构源日历对齐（v2 新增）

价格（`M_CONT`）与总持仓（`KQ.i@m`）来自异构数据源，节假日调整、夜盘安排差异可能
造成交易日日历不一致。数据准备层必须：
- 以**价格日历为基准**做 join（`merge(how="left", on="dt")`）；
- 持仓侧缺失日期 → **NaN**（fail-closed），**严禁** ffill 或静默丢行——错行比
  缺行更危险，缺行会被 NaN 传播拦下，错行会伪装成信号。

## 4. 模块设计

- **路径**：`cascade/oi_gated_momentum.py`（独立模块，纯函数、无 I/O、确定性可复现）
- **API**：

```python
def compute_oi_gated_momentum(
    price: pd.Series,      # 已收盘日收盘价 (index=DatetimeIndex, 由 get_safe_daily 保证)
    total_oi: pd.Series,   # 全市场总持仓, 同一日历、同为已收盘 bar (经 §3.4 对齐)
    k: int = 120,          # 定标窗口, 冻结
    q_price: float = 0.75, # 价格分位数, 冻结
    q_oi: float = 0.85,    # 持仓分位数(带符号), 冻结
) -> pd.Series:
    """返回日频信号序列, float, NaN=不可用 (fail-closed)。
    输入契约: 两序列同窗对齐于已收盘 bar; 模块不内部 shift。"""
```

- **调用方**：`scripts/extract_xreg.py` 协变量注册 + cascade 特征流水线（慢环
  aligned 评估消费）；快环经 covariate menu 的机制说明引用本 spec，不直接调用；
- 参数视为**冻结常量**：不允许运行时注入覆盖，慢环无调参自由度。

## 6. 验收清单（实施时逐项检查）

1. 模块级测试：
   - 门控四象限表逐格断言（§2.1 四行情 → 输出符号/零）；
   - **同窗对齐测试（v2）**：signal_t 依赖 bar t 的 price 与 OI、不依赖 t 之后的
     任何 bar；输入序列含未收盘 bar 的场景由调用方掩码负责（模块以纯函数边界
     测试代替）；
   - **非对称定标测试（v2）**：窗口内注入极端负 ΔOI（减仓踩踏），scale_OI 与门控
     激活度不变（带符号 85% 分位免疫下尾）；
   - **算子钉死测试（v2）**：构造价格/OI 序列断言 pct_change(5) 语义（相对变化），
     diff(5) 语义下测试必然失败；
   - NaN/inf/bool 输入传播 NaN；分位数 ≤1e-6 → NaN（§3.3 断言）；预热期 NaN；
   - 确定性：同输入两次调用逐位相等。
2. 数据级验收：`index_continuous_1d` 覆盖 2016-01-05→今且 OI 无空洞；与 M_CONT
   日历 inner 差集为空或可解释；换月日 ΔOI 无翻倍跳变（对比主力单合约序列）。
3. 集成验收：评估器 gated 通用开关落地且**既有协变量裁决逐位不变**（回归零漂移）；
   extract_xreg 注册后慢环 aligned eval 可消费。
