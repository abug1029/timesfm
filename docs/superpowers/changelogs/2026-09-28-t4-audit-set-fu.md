# T4 Changelog: 审计集裁定记录 — `fu` 加入审计集

**Status:** ✅ 文档化完成

**来源:** PR-B5 评审 H2

## 问题描述

PR-B5 三路消融审计集配置（`config/ablation_audit_config.json`）包含 7 个品种：
```json
"symbols": ["ss", "sr", "m", "jd", "lh", "cj", "fu"]
```

其中 `fu`（燃油）是**新增品种**，触及 spec §4.2 W2.3「固定审计集」的"固定"语义。

## spec 相关条款（解释性引用，非直接引文）

**spec §4.2 W2.3** 提及"固定小型审计集（§1.1 L2：2–3 品种 × 少量代表性协变量）"，
但未明确定义"固定"是否允许后续扩充。

**解释性理解**（基于 spec 整体精神）：
- 审计集应在研究初期锁定，以保证跨阶段可比性
- 但若新品种满足特定条件（无历史裁决、使用新协议指纹），扩充不会破坏已有裁决的可比性
- `comparable()` 守卫通过 `protocol_fingerprint` 过滤阻止跨协议比较

> **注意**: 以上是对 spec 的解释性理解，非直接引文。实际 spec 文本见
> §4.2 W2.3 表格及 §1.1 L2 的引用。

## 裁定

### 审计集扩充的合法性

**裁定: 允许，但须满足以下条件：**

1. **新品种 `fu` 无历史裁决**：
   - `fu` 在 Stage 1/2 的 registry 中无任何裁决记录
   - 因此不存在"与旧裁决的可比性"问题
   - 扩充不影响已有 143 条裁决的可比性

2. **`fu` 的基线将使用新协议指纹**：
   - D5 修复后，协议指纹已包含 cutoff 约定（`protocol_v2`）
   - `fu` 的 nocov 基线将在 T1a 中使用新协议指纹生成
   - 与旧品种的新基线口径一致

3. **跨阶段可比性保护**：
   - Stage 1/2 的裁决（143 条）不包含 `fu`，不受影响
   - Stage 3 的新裁决（含 `fu`）使用新协议指纹，与旧裁决**协议不兼容**（设计意图）
   - `comparable()` 守卫会正确阻止跨协议比较

### 审计集"固定"语义的重新定义

**⚠️ Spec 解释修订（v2 新增）**: 以下为对 spec §4.2 W2.3 "固定审计集"的解释性修订，
非 spec 原文。此修订需宿主确认。

**原解释**: 审计集在 Stage 1 出口时锁定，不得变更

**新解释（裁定后）**: 
- 审计集的"固定"指**研究目标固定**，而非品种集合绝对不变
- 新增品种若满足以下条件，允许加入：
  1. 该品种在旧阶段无裁决记录（不破坏可比性）
  2. 新品种的基线使用当前协议指纹
  3. 在报告中显式声明审计集变更

**依据**: spec §4.2 W2.3 引用 §1.1 L2 的"固定小型审计集"，但未明确定义"固定"的边界。
本解释认为"固定"的核心是保护跨阶段可比性，而非绝对禁止品种扩充。

## 影响分析

### 正面影响

1. **覆盖度提升**：`fu` 属于 energy_chem 板块，加入后审计集覆盖更完整
2. **无直接兼容性风险**：`fu` 无历史裁决，不破坏已有 143 条裁决的可比性
3. **协议守卫有效**：`comparable()` 会正确阻止新旧协议的不当比较

### 潜在风险

1. **语义重新定义的政策风险**：
   - 将"固定审计集"从绝对不变重新解释为条件可变，是政策变更
   - 未来可能有更多品种要求加入，需明确"固定"的边界条件
   - **缓解**: 在报告中显式声明此解释修订，并要求宿主确认

2. **审计集规模问题**：
   - spec §1.1 L2 提及"2–3 品种"，现扩充至 7 品种
   - 是否仍符合"固定小型审计集"的定义？需评估
   - **缓解**: 在 Stage 3 报告中说明审计集规模变化的理由

3. **`fu` 数据质量未知**：
   - `fu` 无历史裁决，模型对其预测能力未知
   - 需先跑冒烟测试验证 checkpoint 可用性
