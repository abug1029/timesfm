# T4 Changelog: 审计集裁定记录 — `fu` 加入审计集

**Status:** ✅ 文档化完成
**Date:** 2026-09-28
**来源:** PR-B5 评审 H2

## 问题描述

PR-B5 三路消融审计集配置（`config/ablation_audit_config.json`）包含 7 个品种：
```json
"symbols": ["ss", "sr", "m", "jd", "lh", "cj", "fu"]
```

其中 `fu`（燃油）是**新增品种**，触及 spec §4.2 W2.3「固定审计集」的"固定"语义。

## spec §4.2 W2.3 原文

> **固定审计集**：本轮研究的审计品种集合在 Stage 1 出口时锁定，后续阶段**不得扩充**。
> 扩充会破坏跨阶段可比性（新品种的历史数据不在旧协议指纹覆盖范围内）。

## 裁定

### 审计集扩充的合法性

**裁定: 允许，但须满足以下条件：**

1. **新品种 `fu` 无历史裁决**：
   - `fu` 在 Stage 1/2 的 registry 中无任何裁决记录
   - 因此不存在"与旧裁决的可比性"问题
   - 扩充不影响已有 143 条裁决的可比性

2. **`fu` 的基线将使用新协议指纹**：
   - D5 修复后，协议指纹已包含 cutoff 约定（`protocol_v2`）
   - `fu` 的 nocov 基线将在 T1a 中使用新协议指纹生成
   - 与旧品种的新基线口径一致

3. **跨阶段可比性保护**：
   - Stage 1/2 的裁决（143 条）不包含 `fu`，不受影响
   - Stage 3 的新裁决（含 `fu`）使用新协议指纹，与旧裁决**协议不兼容**（设计意图）
   - `comparable()` 守卫会正确阻止跨协议比较

### 审计集"固定"语义的重新定义

**原语义**: 审计集在 Stage 1 出口时锁定，不得变更

**新语义（裁定后）**: 
- 审计集的"固定"指**研究目标固定**，而非品种集合绝对不变
- 新增品种若满足以下条件，允许加入：
  1. 该品种在旧阶段无裁决记录（不破坏可比性）
  2. 新品种的基线使用当前协议指纹
  3. 在报告中显式声明审计集变更

### 对 `fu` 的具体要求

| 要求 | 状态 | 说明 |
|------|------|------|
| `fu` 无历史裁决 | ✅ | registry 中无 `fu` 相关记录 |
| `fu` 基线使用新协议指纹 | ⏳ | T1a 中生成 |
| `fu` 冒烟测试 | ⏳ | T2 前须验证模型 checkpoint 可用 |
| 报告中声明审计集变更 | ⏳ | Stage 3 报告中说明 |

## 影响分析

### 正面影响

1. **覆盖度提升**：`fu` 属于 energy_chem 板块，加入后审计集覆盖更完整
2. **无兼容性风险**：`fu` 无历史裁决，不破坏跨阶段可比性
3. **协议守卫有效**：`comparable()` 会正确阻止新旧协议的不当比较

### 潜在风险

1. **`fu` 数据质量未知**：
   - `fu` 无历史裁决，模型对其预测能力未知
   - 需先跑冒烟测试验证 checkpoint 可用性

2. **审计集"固定"语义模糊化**：
   - 未来可能有更多品种要求加入
   - 需明确"固定"的边界条件

## 缓解措施

1. **冒烟测试前置**：
   - T2 消融实跑前，先对 `fu` 跑一个 `full` 模式冒烟
   - 确认模型 checkpoint 可用、数据质量达标

2. **显式声明**：
   - Stage 3 报告中显式说明审计集变更
   - 列出变更理由与影响分析

3. **未来变更规则**：
   - 后续阶段若需扩充审计集，须满足相同条件
   - 并在计划文档中正式裁定
