## 三、问题诊断

### 问题 1：提案生成缺乏去重机制 ⚠️ P0

**现象**: 89.2% 冗余率，平均每个 variant 重复 9.3 次

**根因分析**:
1. 生成过程未检查已存在的 variant_id
2. 不同 run/generation 之间缺乏协调
3. 可能使用了相同的随机种子或生成策略

**影响**:
- 浪费 89.2% 的 prescreen 计算资源
- 慢环队列被重复提案占据（当前 404 个待处理）
- 无法聚焦于真正的新想法
- 高重复 variant 通过率（18.8%）低于平均水平

**证据**:
- Top 10 重复 variant 中，calendar_cyclical 占 5 个
- 重复≥50次的 variant 通过率仅 18.8%（vs 平均 34.0%）

### 问题 2：验证瓶颈 ⚠️ P0

**现象**: 仅 6.5% 提案完成验证，404 个待处理

**根因分析**:
1. 慢环处理能力有限（单进程，~400 待处理）
2. 验证优先级策略不明确
3. 可能优先验证了高重复 variant，浪费资源

**影响**:
- 无法快速反馈提案质量
- 堆积的提案可能已过时
- 无法及时调整生成策略

**证据**:
- 已验证 480 个，待验证 6909 个
- 慢环日志显示正在处理第 401 个待处理提案

### 问题 3：质量未随 generation 提升 ⚠️ P1

**现象**: gen_0/1/2 通过率一致（~23%），无明显演进

**根因分析**:
1. 选择压力不足：未基于历史成功率调整生成策略
2. 变异策略未针对成功特征优化
3. 评估标准未反馈到生成过程
4. 可能缺乏精英保留机制

**影响**:
- 无法持续提升提案质量
- 长期维持低效状态
- 资源浪费在低质量提案上

**证据**:
- gen_0: 23.1% 通过率
- gen_1: 23.7% 通过率
- gen_2: 22.7% 通过率
- 三者几乎无差异

### 问题 4：部分 Symbol/Family 表现极差 ⚠️ P1

**现象**: 
- eg/lh/i/jm/ma: 0% 通过率
- ccl/basis_momentum/stddev/oi_gated_momentum/hurst: 0-1.1% 通过率

**根因分析**:
1. 这些 symbol/family 的协变量可能本身预测能力弱
2. 生成策略未针对 symbol 特性调整
3. 可能存在系统性偏差（如数据质量问题）

**影响**:
- 大量资源浪费在低效 symbol/family 上
- 拉低整体通过率

**证据**:
- eg: 903 个提案，0% 通过率
- lh: 407 个提案，0% 通过率
- ccl: 620 个提案，1.1% 通过率
- basis_momentum: 638 个提案，0% 通过率

### 问题 5：验证覆盖率低导致无法准确评估 ⚠️ P1

**现象**: 仅 6.5% 提案完成验证

**根因分析**:
1. 验证速度慢于生成速度
2. 缺乏智能采样策略
3. 未优先验证高潜力提案

**影响**:
- 无法准确评估整体质量分布
- 无法识别高效/低效 symbol/family
- 无法及时调整策略

**证据**:
- 7389 个提案，仅 480 个已验证
- 部分 symbol/family 验证样本过小（如 cf: 2 个，p: 14 个）

## 四、优化建议

### P0（立即执行，1-2 周）

#### 建议 1：实施去重机制

**目标**: 将冗余率从 89.2% 降至 <10%

**方案**:
1. **生成前去重**:
   - 维护全局 variant_id 集合
   - 生成前查询是否已存在
   - 跳过已存在的 variant

2. **跨 run 协调**:
   - 建立共享的 variant 注册表
   - 不同 run 之间同步已生成 variant

3. **清理现有队列**:
   - 扫描慢环队列，去除重复提案
   - 优先验证唯一 variant

**预期效果**:
- 减少 80%+ 冗余提案
- 释放慢环队列空间
- 聚焦于真正的新想法

**实施难度**: 中等  
**风险**: 低

#### 建议 2：加速验证流程

**目标**: 将验证覆盖率从 6.5% 提升至 30%+

**方案**:
1. **并行化慢环处理**:
   - 启动多个慢环进程
   - 按 symbol/family 分配任务

2. **优先级策略**:
   - 优先验证新生成提案
   - 优先验证唯一 variant
   - 优先验证高潜力 symbol/family

3. **快速预筛**:
   - 利用现有 prescreen 结果（34% 通过率）
   - 仅对 prescreen 通过的提案进行深度验证

**预期效果**:
- 提升验证速度 3-5 倍
- 快速反馈提案质量
- 及时调整生成策略

**实施难度**: 中等  
**风险**: 低

### P1（短期优化，2-4 周）

#### 建议 3：引入质量反馈循环

**目标**: 实现 generation 间质量提升（每代 +5%）

**方案**:
1. **分析成功特征**:
   - 提取通过提案的共同特征
   - 识别高效 symbol/family
   - 分析 mechanism 关键词

2. **调整生成策略**:
   - 高通过率 symbol/family 增加探索
   - 低通过率 symbol/family 减少资源投入
   - 基于成功特征调整 mutation rate

3. **精英保留**:
   - 保留高质量提案作为种子
   - 基于精英提案生成变异体

**预期效果**:
- 通过率从 34% 提升至 50%+
- 高质量率从 31.9% 提升至 40%+
- 实现持续质量改进

**实施难度**: 高  
**风险**: 中

#### 建议 4：分层验证策略

**目标**: 减少无效深度验证，提升验证效率

**方案**:
1. **三级验证**:
   - L1: 快速预筛（已实现，34% 通过率）
   - L2: 轻量验证（100-200 时间点）
   - L3: 深度验证（588 时间点，仅针对 L2 通过）

2. **动态调整**:
   - 根据 L1/L2 通过率调整 L3 阈值
   - 高通过率 symbol/family 降低 L2 阈值
   - 低通过率 symbol/family 提高 L2 阈值

**预期效果**:
- 减少 50%+ 无效深度验证
- 提升验证吞吐量
- 更快反馈提案质量

**实施难度**: 高  
**风险**: 中

#### 建议 5：针对低效 symbol/family 的专项优化

**目标**: 提升 eg/lh/ccl/basis_momentum 等低效类别的表现

**方案**:
1. **根因分析**:
   - 检查数据质量问题
   - 分析失败提案的共同特征
   - 识别系统性偏差

2. **针对性调整**:
   - 调整 symbol-specific 生成参数
   - 修改 family-specific 评估标准
   - 引入 domain knowledge

3. **暂停或减少**:
   - 对持续低效的 symbol/family 暂停生成
   - 将资源转移到高效类别

**预期效果**:
- 识别并解决系统性问题
- 减少 30%+ 低效提案
- 提升整体通过率

**实施难度**: 中  
**风险**: 中

### P2（中期改进，1-3 月）

#### 建议 6：动态调整生成参数

**目标**: 自适应调整生成策略，最大化质量

**方案**:
1. **强化学习框架**:
   - 将生成过程建模为 MDP
   - 状态：历史通过率、symbol/family 分布
   - 动作：mutation rate、探索/利用比例
   - 奖励：通过率、高质量率

2. **多臂老虎机**:
   - 每个 symbol/family 作为一个臂
   - 根据历史表现动态分配资源
   - UCB 或 Thompson Sampling 策略

3. **实时监控**:
   - 跟踪关键指标（通过率、高质量率、冗余率）
   - 自动触发参数调整
   - A/B 测试不同策略

**预期效果**:
- 自动化优化生成策略
- 持续提升质量
- 减少人工干预

**实施难度**: 高  
**风险**: 高

#### 建议 7：建立质量预测模型

**目标**: 预测未验证提案的质量，优先验证高潜力提案

**方案**:
1. **特征工程**:
   - 提取提案特征（symbol、family、mechanism 关键词、长度等）
   - 利用已验证的 480 个样本作为训练数据

2. **模型选择**:
   - 二分类：预测是否通过 gate
   - 回归：预测 dir_acc 值
   - 模型：XGBoost、LightGBM、随机森林

3. **应用**:
   - 对未验证提案进行预测
   - 优先验证高预测质量的提案

### 8.2 分析方法

- **统计分析**: 描述性统计、分布分析、相关性分析
- **分组对比**: 按 symbol/family/generation/时间分组
- **趋势分析**: 时间序列分析
- **质量评估**: 基于慢环验证结果（gate_pass、tier）

### 8.3 指标定义

- **通过率**: gate_pass=True 的提案数 / 已验证提案数
- **高质量率**: tier=S 或 A 的提案数 / 已验证提案数
- **冗余率**: (总提案数 - 唯一 variant 数) / 总提案数
- **验证覆盖率**: 已验证提案数 / 总提案数
